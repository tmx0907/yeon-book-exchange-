## 1. 인증 보안 (Authentication)

### ✅ 체크리스트

| # | 항목 | 중요도 | 설명 |
|---|------|:------:|------|
| 1.1 | 비밀번호 해싱 | 🔴 필수 | 절대 평문 저장 금지 (bcrypt, argon2 사용) |
| 1.2 | 세션 타임아웃 | 🟡 권장 | 비활성 사용자 자동 로그아웃 (30분) |
| 1.3 | 로그인 시도 제한 | 🔴 필수 | 5회 실패 시 계정 잠금 또는 지연 |
| 1.4 | 이메일 인증 | 🟡 권장 | 회원가입 시 이메일 확인 |
| 1.5 | 비밀번호 강도 검사 | 🟡 권장 | 8자 이상, 대소문자+숫자+특수문자 |
| 1.6 | JWT 토큰 만료 | 🔴 필수 | 액세스 토큰 1시간, 리프레시 7일 |
| 1.7 | 소셜 로그인 검증 | 🟡 권장 | OAuth 리다이렉트 URL 화이트리스트 |

### 🤖 AI 프롬프트

```
내 앱에 [Supabase/Firebase/NextAuth] 인증을 추가해줘.

보안 요구사항:
- 비밀번호는 절대 평문 저장하지 않기
- 30분 비활성 시 자동 로그아웃
- 5회 로그인 실패 시 15분 잠금
- 이메일 인증 필수
- 비밀번호 최소 8자, 대소문자+숫자 포함

[프레임워크: React/Next.js/Vue]
[백엔드: Supabase/Firebase/Node.js]
```

## 2. 데이터 보안 (Data Protection)

### ✅ 체크리스트

| # | 항목 | 중요도 | 설명 |
|---|------|:------:|------|
| 2.1 | RLS (Row Level Security) | 🔴 필수 | 사용자별 데이터 접근 제한 |
| 2.2 | 입력값 검증 | 🔴 필수 | 모든 사용자 입력 필터링 |
| 2.3 | SQL Injection 방지 | 🔴 필수 | 파라미터화된 쿼리 사용 |
| 2.4 | XSS 방지 | 🔴 필수 | HTML 이스케이프 처리 |
| 2.5 | 민감정보 암호화 | 🔴 필수 | 주민번호, 카드번호 등 암호화 저장 |
| 2.6 | 데이터 백업 | 🟡 권장 | 정기적 백업 및 복구 테스트 |
| 2.7 | 감사 로그 | 🟡 권장 | 중요 작업 로깅 (삭제, 수정 등) |

### 🤖 AI 프롬프트

```
내 Supabase 데이터베이스에 보안을 강화해줘.

요구사항:
1. RLS(Row Level Security) 활성화
   - users 테이블: 본인 데이터만 읽기/수정 가능
   - posts 테이블: 누구나 읽기, 본인만 쓰기/삭제
   - private_messages 테이블: 발신자/수신자만 접근

2. 모든 INSERT/UPDATE에 입력값 검증 추가
3. 중요 작업 시 activity_logs 테이블에 기록

SQL 정책 코드와 함께 설명해줘.
```

## 3. API 보안

### ✅ 체크리스트

| # | 항목 | 중요도 | 설명 |
|---|------|:------:|------|
| 3.1 | HTTPS 강제 | 🔴 필수 | HTTP 접근 차단 |
| 3.2 | API Rate Limiting | 🔴 필수 | IP당 요청 제한 (100/분) |
| 3.3 | CORS 설정 | 🔴 필수 | 허용된 도메인만 접근 |
| 3.4 | API 키 보호 | 🔴 필수 | 환경변수로 관리, 클라이언트 노출 금지 |
| 3.5 | 에러 메시지 | 🟡 권장 | 상세 에러 숨기기 (프로덕션) |
| 3.6 | 요청 크기 제한 | 🟡 권장 | 업로드 파일 크기 제한 |

### 🤖 AI 프롬프트

```
내 API 보안을 강화해줘.

현재 환경:
- 프론트엔드: [Vercel/Netlify]
- 백엔드: [Supabase/Firebase/자체 서버]
- 도메인: myapp.com

요구사항:
1. CORS 설정: myapp.com, localhost:3000만 허용
2. Rate Limiting: IP당 분당 100 요청
3. API 키는 환경변수로 관리
4. 프로덕션에서 상세 에러 메시지 숨기기
5. 파일 업로드 최대 5MB 제한

각 설정의 코드와 설명을 포함해줘.
```

| # | 항목 | 중요도 | 설명 |
|---|------|:------:|------|

| 4.2 | XSS 방지 | 🔴 필수 | dangerouslySetInnerHTML 사용 금지 |
| 4.3 | 민감정보 노출 방지 | 🔴 필수 | 콘솔 로그에 비밀번호/토큰 출력 금지 |
| 4.4 | Error Boundary | 🟡 권장 | 예외 발생 시 안전한 폴백 UI |
| 4.5 | 의존성 보안 | 🟡 권장 | npm audit로 취약점 검사 |

### 🤖 AI 프롬프트

```
내 React 앱의 프론트엔드 보안을 점검해줘.

체크해야 할 항목:
1. 환경변수가 제대로 분리되어 있는지 (.env 파일 검토)
2. 민감정보가 console.log로 출력되는지
3. XSS 취약점이 있는지 (dangerouslySetInnerHTML 사용 여부)
4. Error Boundary가 적용되어 있는지
5. npm audit 결과 취약점이 있는지

문제가 있으면 수정 코드도 함께 제공해줘.
```

## 6. AI 프롬프트 템플릿

### 🎯 새 프로젝트 시작 시

```
새 웹 앱 프로젝트를 시작하려고 해.

📌 프로젝트 정보:
- 앱 이름: [앱 이름]
- 목적: [앱 설명]
- 사용자: [타겟 사용자]

📌 기술 스택:
- 프론트엔드: React + TypeScript + Vite
- 백엔드: Supabase
- 배포: Vercel
- 스타일: Tailwind CSS

📌 보안 요구사항 (필수 적용):
1. 인증: Supabase Auth + 이메일 인증
2. 30분 비활성 시 자동 로그아웃
3. RLS 정책으로 사용자별 데이터 격리
4. 모든 API 키는 환경변수로 관리
5. Error Boundary 적용
6. 입력값 검증 (프론트+백엔드)

프로젝트 구조와 초기 설정 코드를 만들어줘.
```

### 🔍 보안 점검 요청 시

```
내 코드의 보안을 점검해줘.

확인해야 할 파일:
- [파일 경로 1]
- [파일 경로 2]

체크리스트:
□ 하드코딩된 비밀번호/API 키가 있는가?
□ 사용자 입력이 검증되고 있는가?
□ SQL Injection 가능성이 있는가?
□ XSS 취약점이 있는가?
□ 민감정보가 로그에 출력되는가?
□ 적절한 에러 처리가 되어 있는가?

문제가 발견되면 수정 코드와 함께 설명해줘.
```

### 🚀 배포 직전 최종 점검

```
앱 론칭 직전 보안 최종 점검을 해줘.

□ npm audit으로 취약점 검사
□ TypeScript 타입 체크 (tsc --noEmit)
□ 프로덕션 빌드 테스트
□ .env 파일이 .gitignore에 있는지
□ 환경변수가 Vercel에 설정되어 있는지
□ HTTPS 적용 확인
□ Error Boundary 작동 확인
□ 콘솔에 민감정보 출력 여부

각 항목 결과를 표로 정리하고,
문제가 있으면 해결 방법을 알려줘.
```
